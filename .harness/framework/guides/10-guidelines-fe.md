# FE 项目指导

本文是项目无关的后台管理类 FE 指导，用于从成熟后台系统中提炼可复用的信息架构、组件语义、布局模式、视觉规范、交互规范和安全边界。

具体项目应根据自身技术栈、运行方式、团队规模和业务复杂度进行裁剪，不应直接复制参考项目的工程依赖、历史实现和技术债务。

约束：AI ReadOnly，未经人工确认、禁止AI修改。

---

# 一、适用范围

本指导适用于以下类型的前端页面：

* 管理后台
* 控制台
* 运营平台
* 数据管理页面
* 资源管理页面
* 检索、诊断、监控和配置类页面

本指导不强制要求使用特定前端框架。

项目可以使用：

* Vue
* React
* Svelte
* 原生 HTML/CSS/JS
* 服务端模板

关键目标是复用成熟后台产品的信息架构、组件语义和交互模式。

---

# 二、设计原则

## 一致性优先

相同语义应使用相同组件、相同状态表达和相同交互方式。

避免：

* 同义组件重复建设
* 同状态不同颜色
* 同操作不同交互

## 信息架构优先

布局服务于信息架构，而非视觉装饰。

优先考虑：

1. 用户任务路径
2. 导航层级
3. 信息分组
4. 操作可发现性

## Design System 优先

推荐建立统一 Design System。

至少包含：

* Design Token
* 组件规范
* 图标规范
* 色彩规范
* 间距规范
* 状态规范

所有视觉样式应优先通过 Token 驱动。

---

# 三、组件分层

## 基础 UI

基础 UI 是页面最常用的交互原子。

统一规范：

* Button
* Input
* Textarea
* Select
* Checkbox
* Radio
* Switch
* DatePicker
* Form
* Table
* Dialog
* Drawer
* Tooltip
* Popover
* Message
* Notification
* Alert
* Progress
* Tag
* Badge

要求：

* 状态完整
* 可访问
* 支持主题化
* 支持禁用态
* 支持 Loading

禁止重复定义语义相同的基础组件。

## 后台壳组件

后台壳组件定义应用级信息架构。

常见组件：

* App Shell
* Sidebar
* Header
* Top Navigation
* Breadcrumb
* Page Header
* Content Container
* Tab
* Global Search
* User Menu

要求：

* 导航结构稳定
* 页面结构稳定
* 业务逻辑与壳层解耦

## 复杂表格

适用于：

* 宽表
* 多状态列表
* 大数据量管理页

要求：

* 固定关键列
* 固定操作列
* 批量操作
* 列过滤
* 排序
* 分页
* 空状态
* 错误状态
* Loading 状态

超过千级数据量时优先考虑虚拟滚动。

## 辅助面板

用于降低主页面复杂度。

包括：

* Drawer
* Collapse
* Steps
* Card
* Split Panel

详情信息优先使用详情区域或 Drawer 承载。

## 可视化组件

图表用于辅助分析。

要求：

* 图表必须提供数值信息
* 不依赖颜色表达结论
* 支持空状态
* 支持加载状态

推荐统一图表组件库。

## 编辑器与结构化文本

适用于：

* Code
* JSON
* YAML
* Markdown
* Diff
* Log

要求：

* 等宽字体
* 可复制
* 长文本局部滚动
* 不可信内容默认按文本渲染

# 四、页面布局

## 整体框架

推荐结构：

1. Header
2. Sidebar
3. Content Area
4. Business Components

原则：

* 导航稳定
* 内容聚焦
* 层级清晰

## 左侧导航

规范：

* 展开宽度：180~240px
* 折叠宽度：56~72px
* 当前项明确高亮
* 长菜单内部滚动

避免：

* 动态重排菜单
* 导航中嵌入复杂业务逻辑

## 顶栏

包含：

* 品牌区
* 折叠按钮
* 全局导航
* 搜索
* 通知
* 用户菜单

原则：

* 仅承载全局能力
* 高度保持稳定

## 页内 Tab

仅表达页面内部内容切换。

禁止替代全局导航。

## 内容区

规范：

* 页面边距统一
* 卡片化组织内容
* 长内容局部滚动
* 页面状态可恢复

---

# 五、组件规范

## 表单

规范：

* Label + Control + HelpText
* 必填项明确标记
* 错误信息贴近字段
* 高级筛选可折叠

支持：

* 键盘操作
* 自动聚焦
* 无障碍访问

## 表格

规范：

* 状态使用 Badge/Tag
* 操作列固定
* 危险操作二次确认
* 支持 Empty State

建议列顺序：

1. 名称
2. 分类
3. 状态
4. 时间
5. 操作

## 卡片与详情

规范：

* 信息按领域分组
* 编辑态与只读态区分
* 长文本默认折叠

## 状态与反馈

要求：

* 所有异步操作必须反馈状态
* 禁止静默失败
* 长任务展示进度

状态语义统一：

* Success
* Running
* Warning
* Error
* Unknown

---

# 六、视觉规范

## Design Token

推荐统一管理：

* Color
* Spacing
* Radius
* Shadow
* Typography
* Motion

业务代码禁止硬编码设计值。

## 色彩

原则：

* 状态颜色全站统一
* 不依赖颜色表达信息
* 保证足够对比度

## 间距

推荐：

* 4
* 8
* 12
* 16
* 24
* 32

形成统一尺度系统。

## 密度

后台默认中等密度。

根据场景调整：

* 列表页偏紧凑
* 详情页偏舒适

---

# 七、交互规范

## 导航状态

要求：

* URL 与导航状态一致
* 刷新后状态可恢复
* 面包屑与导航一致

## 异步操作

要求：

* Loading 可见
* 错误可恢复
* 状态可追踪

## 危险操作

必须：

* 二次确认
* 明确影响范围
* 刷新真实数据

## 空状态

必须说明：

* 为什么为空
* 下一步操作
* 是否受筛选影响

---

# 八、工程规范

## TypeScript

中大型项目默认使用 TypeScript。

原则：

* 禁止滥用 any
* 公共接口必须定义类型
* API 返回值必须声明类型

## JavaScript

参考：

* Airbnb JavaScript Style Guide
* ESLint
* Prettier
* 项目官方规范

## CSS 架构

推荐 ITCSS：

1. Settings
2. Tools
3. Generic
4. Elements
5. Objects
6. Components
7. Utilities

## CSS 命名

推荐 BEM：

* Block
* Element
* Modifier

避免：

* 过深选择器
* 全局污染
* 跨组件覆盖

---

# 九、性能规范

要求：

* 路由级代码分割
* 图片按需加载
* 大列表虚拟滚动
* 避免重复请求
* 控制首屏资源体积

建议关注：

* FCP
* LCP
* INP
* CLS

---

# 十、可访问性（Accessibility）

要求：

* 支持键盘导航
* 支持焦点管理
* 图片提供替代文本
* 表单提供 Label
* 满足 WCAG 基本要求

禁止仅依赖颜色表达状态。

---

# 十一、国际化

多语言项目应：

* 禁止硬编码文案
* 支持日期本地化
* 支持数字格式化
* 支持时区处理

---

# 十二、安全与实现约束

## 安全文本渲染

所有外部数据默认按文本渲染。

禁止：

* XSS 注入
* 未过滤 HTML 插入
* 未处理 Markdown 渲染

允许：

* 安全插值
* Sanitizer 后渲染

## 权限边界

前端权限仅用于：

* UI 展示控制
* 操作入口控制

权限校验必须由服务端最终负责。

## 敏感信息

前端不得保存：

* API Key
* 数据库凭据
* Provider Secret
* 内部服务密钥

## 实现裁剪

应复用：

1. 信息架构
2. 导航体系
3. 组件语义
4. 状态表达
5. 交互反馈
6. 安全边界

不应复制：

1. 过时框架
2. 历史技术债务
3. 临时兼容代码
4. 与业务强绑定实现
5. 不必要工程体系
